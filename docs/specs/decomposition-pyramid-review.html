contextWhy C exists — and what's at stake

The one candidate that is genuinely yours, and genuinely untested by the field.

C breaks a question into the sub-questions that must be answered first, down to a bedrock of researchable facts and base rates, then combines the answers back up into one probability. The research dossier found no published evidence either way on whether this helps calibration — our experiment will be among the first direct tests.

Even if C loses on accuracy, it is the only candidate whose output is a readable argument rather than a number with an essay. The portfolio decision already guarantees it a seat: losing means low weight in the architecture pool, not deletion.

decisionThe decomposition tree

One LLM call turns the question into a typed tree with hard structural caps.

Four node types: conjunction ("all of these must happen"), disjunction ("any of these is enough"), conditional chain ("A, then B given A, then C given A and B"), and leaf (bedrock — a base rate, a checkable fact, a direct estimate).

Worked example — "Will Putin visit Iran before Sept 1?"
NodeTypeEstimate
Standing invitation / summit context existsleaf0.80
Putin chooses the trip, given contextleaf (conditional)0.35
Nothing blocks travel (security, health, crisis)leaf (conditional)0.90
Root (chain product)conditional0.25
Three numbers you can argue with individually — that's the whole point.

Caps (all in config): depth ≤ 2, children ≤ 4 per node, never more than 3 multiplied conjuncts. Over-cap trees are pruned, with the pruning recorded in the trace. The decomposer may also answer "this doesn't decompose" — a single leaf, which makes C gracefully equal a careful single pass.

Every node carries a reasoning_type field (default "checklist") so future reasoning modes — like a proven game-theory module — can plug in per-node without redesign.

  • Any node type missing that you expected (e.g. explicit "evidence for/against" nodes)?

decisionBedrock leaves & the outside-view anchor

How the bottom of the pyramid gets its numbers.

Each leaf is estimated by the existing checklist machinery (the same code candidate A uses), pointed at the leaf's sub-question, over the same shared research bundle — no per-leaf web searches in v1. Every leaf must state a reference class and base rate before adjusting. Leaves without an anchor are the classic way pyramids drift into storytelling.

Trade-off accepted in v1: shared evidence means a niche leaf ("does Iran's parliament need to ratify visits?") may lack targeted sources. Per-leaf retrieval is queued for v2 if P1's argument graphs show leaves starving.

Review prompts
  • OK to defer per-leaf retrieval to v2, or is it load-bearing for a fair test of C?

riskError compounding — the enemy — and the guards

Why naive pyramids fail, and the three defenses built in.

Multiply four slightly-off probabilities and the error compounds: 0.7⁴ ≈ 0.24 even when the true joint chance is far higher, because real sub-events are correlated — the world where the first thing happens is usually a world where the others are likelier too. Naive decomposition systematically drags answers toward 0. This is the documented reason decomposition might lose.

  • Clipping: leaf probabilities clip to [0.03, 0.97] before any multiplication — no leaf gets to claim near-certainty it can't earn.
  • Conjunct cap: at most 3 probabilities ever multiply at one node.
  • The holistic blend (next unit) — the structural answer never stands alone.
Review prompts
  • Is the clip range [0.03, 0.97] sane? (Tighter = more protection, less expressiveness.)
  • Any guard you'd add — e.g. an explicit "are these children correlated?" LLM check?

decisionThe 50/50 holistic blend — the key default

The single most consequential number in this spec.

Alongside the pyramid, one direct holistic forecast of the root question runs (same machinery as candidate A). The final answer is a log-odds blend of the two, weighted 0.5 / 0.5 by default.

Why half-and-half: it is the honest statement that we don't yet know whether the structure adds or subtracts accuracy. The P2 experiment measures exactly this — if the pyramid earns trust, the weight moves toward structure; if not, toward holistic. In the worked example: structure says 0.25, holistic says 0.15 → blended ≈ 0.20.

The blend also means C can never be catastrophically worse than A — the failure mode becomes "adds nothing" rather than "poisons the number".

Review prompts
  • Comfortable with 0.5/0.5 as the frozen starting weight?
  • Should the weight be allowed to differ by question type later (config supports it)?

decisionConfidence from disagreement

Where C's confidence label comes from — two signals, combined pessimistically.
  • Weakest link: a multiplied path is only as confident as its least confident leaf.
  • Structure vs. holistic agreement: if the pyramid and the direct estimate disagree sharply, confidence caps at "low" — reusing the same disagreement thresholds the ensemble already uses.

That disagreement is a feature, not noise: "the argument says 0.25 but the gut-check says 0.60" is precisely the kind of case postmortems should dig into.

Review prompts
  • Does "min of the two signals" match your intuition for how cautious the label should be?

contextThe legible argument — what you actually get

The product payoff, independent of the Brier race.

Every C forecast stores the full tree: each node's question, estimate, reference class, rationale, the combination math, the holistic estimate, and the blend. That record is the auditable argument — the thing you asked for on day one ("explanation is core product, just for me") — and it is the designated rendering target for the future web app's forecast view.

At P1 you'll review real printed argument graphs from 2–3 live questions; the test at that gate is "is this argument legible and sane?", explicitly not the score.

contextCost & the config knobs

What a C forecast costs and what you can tune without code.

Per question: one decomposition call (stronger model, ~$0.05) + up to 8 leaf calls (cheap model) + one holistic call ≈ $0.15–0.35. Sits between A (~$0.02) and the 6-member ensemble (~$0.50).

All tunable in settings.toml [pyramid]: max_depth, max_children, max_conjuncts, leaf_clip_low/high, holistic_blend_weight, plus separate model/effort configs for the decomposer, the leaves, and the holistic pass.

decisionGame-theory as a refinement module

Your idea, recorded in the architecture doc in the shape you proposed — confirm it.

A refiner is an optional post-pass on any candidate's forecast: it takes the question, evidence, and current forecast, plays out the interval between now and resolution as a strategic interaction (who decides, what they want, which path is stable), and returns an adjusted probability plus its reasoning — all recorded in the trace.

  • Composable: one module works on top of A, B, C, D, and E.
  • Testable: pre-registered paired experiment, same arm ± refiner.
  • Bounded: full machinery (payoff matrices, equilibrium solving) stays out until the cheap LLM-reasoned version shows signal.
  • C-compatible: via reasoning_type, a proven refiner can later also run inside the pyramid on actor-driven nodes.

Build order: after C's vertical slice (P1), as its own small spec + experiment.
